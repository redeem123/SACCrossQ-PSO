1. EXECUTIVE SUMMARY
================================================================================

APEX-PSO is a state-of-the-art Reinforcement Learning-based Particle Swarm
Optimization algorithm that learns to dynamically optimize PSO parameters for
each particle individually. Unlike traditional PSO algorithms that use fixed
parameters throughout the optimization process, APEX-PSO employs an advanced
neural network trained with Soft Actor-Critic (SAC) learning to adaptively
adjust particle parameters (inertia weight w, cognitive coefficient c1, social
coefficient c2) based on real-time swarm dynamics.

Key Characteristics:
  • Deep Reinforcement Learning: SAC framework with automatic entropy tuning
  • Per-Particle Adaptation: 120-dimensional action space for 40 particles
  • Advanced Monitoring: 45-dimensional context-aware state representation
  • Multi-Objective Optimization: Balances fitness, diversity, convergence speed
  • GPU-Accelerated: Deep learning networks enable rapid training and inference
  • CrossQ Optimizations: BatchNormalization, minimized target networks
  • Temporal Awareness: 5-iteration circular buffer for state aggregation

2. ALGORITHM OVERVIEW
================================================================================

2.1 Core Concept
----------------
Traditional PSO uses fixed parameters throughout the entire optimization process:
  w  ∈ [0.4, 0.9]  (inertia weight, controls momentum)
  c1 ∈ [0.5, 2.5]  (cognitive coefficient, self-learning rate)
  c2 ∈ [0.5, 2.5]  (social coefficient, swarm-learning rate)

APEX-PSO learns a parametric policy π(a|s) that generates particle-specific
parameters at each iteration:
  s(t) = current swarm state (45D)
  a(t) = π(s(t)) = [w_1, c1_1, c2_1, ..., w_40, c1_40, c2_40] (120D)

This allows the algorithm to:
  • Increase inertia weight during exploration phases
  • Decrease inertia weight during exploitation phases
  • Dynamically balance cognitive vs. social learning
  • Respond to diversity loss with increased exploration
  • Accelerate convergence when stagnation is detected

2.2 Training vs. Inference
-------------------------
The algorithm operates in three modes:

[Mode 1: Pretraining]
  Purpose: Learn optimal parameter policy from scratch
  Process: 150 episodes × 600 iterations each
  Duration: 2-4 hours on GPU, 24+ hours on CPU
  Output: Trained SAC agent (policy + value networks)
  Storage: Checkpoints saved every 50 episodes
  Use Case: Initial learning phase, building parameter strategy

[Mode 2: Online Learning]
  Purpose: Learn during actual PSO optimization
  Process: 1 episode × 600 iterations
  Duration: Real-time, no separate training phase
  Advantage: No pretraining required, immediate deployment
  Disadvantage: Slower convergence as agent still learning
  Use Case: Quick testing, rapid prototyping

[Mode 3: Inference (Pretrained)]
  Purpose: Deploy pre-trained agent for fast optimization
  Process: Load trained model, run single PSO episode
  Duration: Single 600-iteration run with learned policy
  Advantage: Fast execution, proven performance
  Disadvantage: Requires prior training phase
  Use Case: Production deployment, competitive testing

3. TECHNICAL ARCHITECTURE
================================================================================

3.1 State Representation (45D)
-----------------------------
APEX-PSO monitors 9 fundamental features that capture swarm dynamics:

Basic Features (9D):
  1. Iteration Progress    : [0, 1] normalized, indicates optimization progress
  2. Population Diversity  : Spatial spread in solution space
  3. Fitness Diversity     : Variance of fitness values in population
  4. Stagnation Duration   : Iterations without fitness improvement
  5. Best Fitness Value    : Log-scaled for better feature scaling
  6. Velocity Magnitude    : Average velocity across all particles
  7. Convergence Pressure  : Distance to global best (diversity metric)
  8. Exploration Indicator : Interaction of diversity and velocity
  9. Fitness Improvement   : Rate of change in best fitness

Temporal Aggregation (45D total):
  The state encoder maintains a circular buffer of 5 consecutive iterations
  and computes multiple statistics:
    • Raw features (9D)         : s(t)
    • Exponential moving average (9D) : λ*s(t-1) + (1-λ)*s(t)
    • Temporal mean (9D)        : mean([s(t-4), ..., s(t)])
    • Temporal standard dev (9D): std([s(t-4), ..., s(t)])
    • Temporal trend (9D)       : s(t) - s(t-1) [delta values]

This 45D state provides rich temporal context about swarm behavior.

3.2 Action Space (120D)
-----------------------
The policy network outputs 120-dimensional continuous actions:

  Raw Output (240D):
    μ(s) = [μ_1, ..., μ_120]       (mean values from actor)
    σ(s) = [σ_1, ..., σ_120]       (log-standard deviation)

  Reparameterization Trick:
    a = tanh(μ + σ ⊙ ε)   where ε ~ N(0, I)

  Parameter Conversion:
    For each particle i ∈ [1, 40]:
      action[3i-2 : 3i] → [w_i, c1_i, c2_i]

    Bounded ranges:
      w_i  ∈ [0.4, 0.9]   (scale tanh output from [-1,1])
      c1_i ∈ [0.5, 2.5]   (scale tanh output from [-1,1])
      c2_i ∈ [0.5, 2.5]   (scale tanh output from [-1,1])

    Formula: param = (range_max - range_min) * (tanh(z) + 1) / 2 + range_min

3.3 Neural Network Architecture
-------------------------------

[ACTOR NETWORK]
  Input: 45D state
  Architecture:
    Layer 1: Linear(45 → 128) + BatchNorm + ReLU
    Layer 2: Linear(128 → 128) + BatchNorm + ReLU
    Layer 3: Linear(128 → 128) + BatchNorm + ReLU
    Output: Linear(128 → 240D) [120 means + 120 log-stds]

  Activation: ReLU for hidden layers, identity for output
  Purpose: Maps state to distribution over actions

[CRITIC NETWORKS (2 Critics)]
  Input: [state (45D), action (120D)] concatenated = 165D
  Architecture (for each critic):
    Layer 1: Linear(165 → 128) + BatchNorm + ReLU
    Layer 2: Linear(128 → 128) + BatchNorm + ReLU
    Layer 3: Linear(128 → 64) + BatchNorm + ReLU
    Output: Linear(64 → 1) [Q-value]

  Purpose: Estimates action value Q(s,a)
  Optimization: Uses minimum of two critics for stability (Clipped Double Q)

[KEY FEATURES]
  • BatchNormalization: Improves training stability and sample efficiency
  • No Target Networks: CrossQ approach, direct Bellman updates
  • Double Q-Learning: min(Q1, Q2) prevents overestimation
  • Automatic Entropy Tuning: Learns temperature coefficient α

3.4 Experience Replay Buffer
----------------------------
Capacity: 1,000,000 transitions
Storage per transition: (s, a, r, s', terminal_flag)
Memory Usage: ~4-5 GB per 1M transitions
Sampling: Uniform random sampling of 512-transition batches
Purpose: Enables off-policy learning, breaks temporal correlations

4. LEARNING ALGORITHM (SAC)
================================================================================

4.1 Soft Actor-Critic (SAC) Overview
------------------------------------
SAC is a maximum-entropy RL algorithm that learns a stochastic policy by
maximizing expected reward plus entropy bonus:

  Objective: J(π) = E[∑_t γ^t (R(s_t, a_t) + α*H(π(·|s_t)))]

  where:
    • R(s_t, a_t) = immediate reward
    • α = temperature coefficient (entropy weight)
    • H(π) = -E[log π(a|s)] = policy entropy

This encourages exploration while maximizing cumulative reward.

4.2 Training Procedure (Per Gradient Step)
------------------------------------------

[STEP 1: Sample Batch]
  • Sample minibatch B of 512 transitions from replay buffer
  • Each transition: (s, a, r, s', done)

[STEP 2: Update Critic Networks]
  For each critic Q_i (i = 1, 2):

    Compute target value using next state:
      a' ~ π(·|s')  [sample action from policy]
      Q_target = r + γ*(1-done)*min(Q_1'(s',a'), Q_2'(s',a')) - α*log π(a'|s')

    Minimize MSE loss:
      L_Q = MSE(Q_i(s,a) - Q_target)

    Update weights: θ_Q ← θ_Q - ∇L_Q

  Purpose: Make Q-network estimates closer to Bellman-backed targets

[STEP 3: Update Actor Network]

  Policy gradient objective:
    J(π) = E_s[E_a~π[Q(s,a) - α*log π(a|s)]]

  Gradient ascent (maximize):
    ∇_θ_π J(π) = ∇_θ_π [Q(s,a) - α*log π(a|s)]

  Update weights: θ_π ← θ_π + ∇J(π)

  Purpose: Improve policy to maximize Q-value with entropy bonus

[STEP 4: Update Temperature Coefficient α]

  Automatic entropy tuning maintains target entropy:
    Target entropy: H_target = -action_dim = -120
    Current entropy: H = E[-log π(a|s)]

  Tuning loss:
    L_α = -α * (H + H_target)

  Update: α ← α - β_α * ∇L_α

  Purpose: Balance exploration (high entropy) with exploitation (low entropy)

[STEP 5: Soft Target Update]
  For both critic networks (not used in CrossQ, but can be enabled):
    θ_target ← τ*θ + (1-τ)*θ_target

  τ = soft update coefficient (typically 0.005)

  Note: APEX-PSO uses CrossQ approach (τ=1, direct updates)

4.3 Hyperparameters
-------------------
Learning Rates:
  • Actor learning rate:     3e-4 (ADAM optimizer)
  • Critic learning rate:    3e-4 (ADAM optimizer)
  • Alpha learning rate:     3e-4 (ADAM optimizer)

Optimization:
  • Optimizer: ADAM (β1=0.9, β2=0.999, ε=1e-8)
  • Batch size: 512 transitions
  • Gradient clipping: Not used in current version

Discount Factor:
  • γ = 0.99 (Future rewards discounted at 99%)
  • Higher γ: values longer-term returns more
  • Lower γ: focuses on immediate rewards

Buffer & Warmup:
  • Replay buffer: 1,000,000 capacity
  • Warmup period: 50 iterations (collect random experience before training)
  • Update frequency: Every iteration (after warmup)

5. REWARD FUNCTION
================================================================================

5.1 Multi-Objective Reward Design
---------------------------------
The reward function balances four competing objectives:

  R(t) = w_f * R_fitness + w_d * R_diversity + w_c * R_convergence + w_curiosity * R_curiosity

  Weights:
    w_f = 1.0  (Primary objective: find good solutions)
    w_d = 0.2  (Secondary: maintain population diversity)
    w_c = 0.1  (Tertiary: converge efficiently)
    w_curiosity = 0.05 (Exploratory bonus)

5.2 Component Details
--------------------

[R_FITNESS: Fitness Reward]
  Objective: Reward better (lower) fitness values
  Formula:
    ΔFitness = best_fitness(t-1) - best_fitness(t)
    R_fitness = ΔFitness / (baseline + ε)

  Behavior:
    • Positive when best fitness improves
    • Magnitude scales with improvement size
    • Zero (or negative) when fitness stagnates

  Example: If best improves from 1600 to 1500, R_fitness = 100/1000 = 0.1

[R_DIVERSITY: Diversity Reward]
  Objective: Prevent premature convergence
  Formula:
    diversity = spatial_spread + fitness_spread
    R_diversity = diversity / (max_possible_diversity)

  Behavior:
    • Higher when population is spread out
    • Penalizes when particles cluster in same region
    • Prevents "convergence death" (all particles at same point)

  Example: Full spread = 1.0, clustered = 0.1

[R_CONVERGENCE: Convergence Speed Bonus]
  Objective: Reward faster optimization
  Formula:
    convergence_speed = 1.0 / (stagnation_iterations + 1)
    R_convergence = improvement_rate * convergence_speed

  Behavior:
    • Positive when swarm is improving rapidly
    • Penalizes long plateaus without progress
    • Discourages endless exploration

  Example: 50 iterations of improvement = high reward, 500 iterations plateau = low reward

[R_CURIOSITY: Exploration Bonus]
  Objective: Encourage exploration of new regions
  Formula:
    exploration = velocity_magnitude * diversity
    R_curiosity = exploration / (baseline + ε)

  Behavior:
    • Bonus for exploring new areas
    • Discounts exploration that doesn't improve fitness
    • Prevents pure exploitation in local optimum

  Example: High velocity + high diversity = 0.3 reward

5.3 Reward Normalization
------------------------
All rewards normalized to [0, 1] range:
  R_normalized = (R - R_min) / (R_max - R_min)

Baseline values learned through experience:
  • Fitness baseline: moving average of historical improvements
  • Diversity baseline: population size * solution dimensionality
  • Convergence baseline: average stagnation duration

6. STATE EXTRACTION PIPELINE
================================================================================

6.1 Feature Extraction Process
------------------------------

[STEP 1: Compute Current Metrics]
  For each iteration t:
    • Particle positions: x_1, ..., x_40 ∈ ℝ^d
    • Particle velocities: v_1, ..., v_40 ∈ ℝ^d
    • Fitness values: f_1, ..., f_40 ∈ ℝ
    • Global best: x_gbest
    • Best fitness: f_best

[STEP 2: Calculate 9 Features]

  Feature 1 - Iteration Progress:
    feature_1 = current_iteration / max_iterations
    Range: [0, 1]
    Interpretation: How far through optimization are we?

  Feature 2 - Population Diversity (Spatial):
    diversity_spatial = mean(||x_i - x_mean||)
    feature_2 = diversity_spatial / max_distance
    Range: [0, 1]
    Interpretation: How spread out are particles?

  Feature 3 - Fitness Diversity:
    diversity_fitness = std([f_1, ..., f_40])
    feature_3 = diversity_fitness / historical_max_std
    Range: [0, 1]
    Interpretation: How varied are fitness values?

  Feature 4 - Stagnation Duration:
    stagnation = iterations_since_best_improvement
    feature_4 = stagnation / max_stagnation_threshold
    Range: [0, 1]
    Interpretation: How long without progress?

  Feature 5 - Best Fitness (Log-Scaled):
    feature_5 = log(f_best + 1) / log(initial_fitness + 1)
    Range: [0, 1]
    Interpretation: Quality of best solution (log scale)

  Feature 6 - Velocity Magnitude:
    velocity = mean(||v_i||)
    feature_6 = velocity / max_velocity
    Range: [0, 1]
    Interpretation: How fast are particles moving?

  Feature 7 - Convergence Pressure (Distance to Best):
    convergence = mean(||x_i - x_gbest||)
    feature_7 = convergence / initial_distance
    Range: [0, 1]
    Interpretation: Are particles clustering around best?

  Feature 8 - Exploration Indicator:
    exploration = diversity_spatial * velocity
    feature_8 = exploration / (max_diversity * max_velocity)
    Range: [0, 1]
    Interpretation: Active exploration or just drifting?

  Feature 9 - Fitness Improvement Rate:
    improvement = (f_best(t-1) - f_best(t)) / max(|f_best(t)|, 1)
    feature_9 = improvement / baseline_improvement_rate
    Range: [-1, 2] (clipped to [0, 1])
    Interpretation: How quickly is fitness improving?

[STEP 3: Temporal Aggregation]
  Maintain circular buffer of 5 most recent iterations:
    history = [s(t-4), s(t-3), s(t-2), s(t-1), s(t)]

  Compute statistics:
    s_raw         = s(t)                    (9D)
    s_ema         = 0.7*s(t-1) + 0.3*s(t)  (9D exponential moving average)
    s_mean        = mean(history)           (9D temporal mean)
    s_std         = std(history)            (9D temporal std)
    s_trend       = s(t) - s(t-1)          (9D temporal delta)

  Concatenate: s_full = [s_raw, s_ema, s_mean, s_std, s_trend] (45D)

[STEP 4: Normalization]
  Apply per-feature normalization:
    s_normalized[i] = (s[i] - mean_i) / (std_i + ε)

  Use running statistics from experience buffer

7. ACTION CONVERSION (Parameter Mapping)
================================================================================

7.1 Action-to-Parameter Mapping
-------------------------------

[STEP 1: Raw Network Output]
  Policy network outputs: 240D vector
    μ = [μ_1, ..., μ_120]        (means)
    σ = [σ_1, ..., σ_120]        (log standard deviations)

[STEP 2: Reparameterization Trick (For Training)]
  Sample noise: ε ~ N(0, I)
  Continuous action: a = tanh(μ + σ ⊙ ε)

  This allows:
    • Differentiable sampling through actor network
    • Maintains stochasticity during training
    • Entropy calculation for policy loss

[STEP 3: Unbounded Action (For Inference)]
  During deployment, can also use:
    a = tanh(μ)  [deterministic greedy policy]

  Or scale std for exploration:
    a = tanh(μ + 0.1*σ)  [epsilon-exploration]

[STEP 4: Parameter Conversion]
  For each particle i ∈ [1, 40]:

    Action index: a_indices = [3i-2, 3i-1, 3i]  [1, 2, 3], [4, 5, 6], ...
    Raw actions: [a_w, a_c1, a_c2] = a[a_indices]  ∈ [-1, 1]³

    Convert tanh output to parameter ranges:
      w_i  = (0.9 - 0.4) * (a_w + 1) / 2 + 0.4   ∈ [0.4, 0.9]
      c1_i = (2.5 - 0.5) * (a_c1 + 1) / 2 + 0.5  ∈ [0.5, 2.5]
      c2_i = (2.5 - 0.5) * (a_c2 + 1) / 2 + 0.5  ∈ [0.5, 2.5]

    General formula:
      param = (param_max - param_min) * (tanh(z) + 1) / 2 + param_min

[STEP 5: Particle Update]
  Standard PSO update with learned parameters:
    v_i(t+1) = w_i*v_i(t) + c1_i*r1*(p_best_i - x_i(t)) + c2_i*r2*(g_best - x_i(t))
    x_i(t+1) = x_i(t) + v_i(t+1)

  where r1, r2 ~ U[0, 1]

8. TRAINING PROCEDURE
================================================================================

8.1 Complete Training Loop
--------------------------

For episode = 1 to num_episodes:

  [INITIALIZE EPISODE]
    • Reset PSO population randomly
    • Initialize best fitness to infinity
    • Clear state encoder buffer

  [WARMUP PHASE (50 iterations)]
    For iter = 1 to 50:
      • Use random actions (explore action space)
      • Collect experience without training networks
      • Fill replay buffer and state buffer

  [MAIN TRAINING PHASE (600 iterations)]
    For iter = 51 to 600:

      [1. Get Current State]
        s(t) ← extract_features(population, best_fitness)
        s(t) ← aggregate_temporal(s(t), history)

      [2. Generate Actions]
        a(t) ~ π(·|s(t))    [sample from policy]
        params ← convert_action_to_params(a(t))

      [3. Execute PSO Step]
        for particle i:
          v_i ← w_i*v_i + c1_i*r1*(pbest_i - x_i) + c2_i*r2*(gbest - x_i)
          x_i ← x_i + v_i
          evaluate f_i

      [4. Compute Reward]
        r(t) ← compute_multi_objective_reward(...)

      [5. Get Next State]
        s(t+1) ← extract_features(population, best_fitness)
        s(t+1) ← aggregate_temporal(s(t+1), history)

      [6. Store Experience]
        replay_buffer.add((s(t), a(t), r(t), s(t+1), done))

      [7. Train Networks (60 gradient steps)]
        For g = 1 to 60:

          [Sample Batch]
            B ← replay_buffer.sample(batch_size=512)

          [Update Critics]
            For each critic Q_i (i=1,2):
              L_Q ← compute_critic_loss(Q_i, B)
              θ_Q ← θ_Q - α_Q * ∇L_Q

          [Update Actor]
            L_π ← compute_actor_loss(π, Q, B, α)
            θ_π ← θ_π + α_π * ∇L_π

          [Update Alpha]
            L_α ← compute_alpha_loss(H, H_target)
            α ← α - α_α * ∇L_α

  [END EPISODE]
    if episode % 50 == 0:
      save_checkpoint(agent, episode)

    log_statistics(episode_return, avg_fitness, final_diversity)

8.2 Convergence Monitoring
--------------------------
Track per-episode metrics:
  • Episode Return: Sum of all rewards in episode
  • Average Fitness: Mean of best fitness value
  • Final Diversity: Population diversity at episode end
  • Policy Entropy: Current policy entropy
  • Critic Loss: Mean MSE loss of critic networks
  • Actor Loss: Mean policy gradient magnitude

Early stopping if:
  • Validation fitness plateau for 30 episodes
  • Loss becomes NaN or Inf
  • GPU memory exhaustion

    standard_pso_update_with_params(params)

    compute_fitness(population)
    update_best_solution()

  [6. Loop]
    continue if not converged

Output:
  • Best solution found
  • Fitness trajectory
  • Parameter usage statistics

10. COMPARISON WITH BASELINES
================================================================================

10.1 Fixed Parameter PSO
------------------------
Standard PSO:
  w = 0.7 (fixed)
  c1 = 1.5 (fixed)
  c2 = 1.5 (fixed)

Disadvantages:
  • Same parameters throughout optimization
  • Cannot adapt to changing swarm dynamics
  • May oscillate around optimum
  • No balance adjustment between exploration/exploitation

10.2 Linearly Decreasing Inertia (PSO-DI)
-----------------------------------------
PSO with parameter decay:
  w(t) = w_initial - (w_initial - w_final) * t / max_iterations
  c1 = 1.5 (fixed)
  c2 = 1.5 (fixed)

Disadvantages:
  • Hand-crafted decay schedule
  • No feedback from swarm state
  • May not match problem characteristics
  • Static cognitive/social balance

10.3 SAEPSO (Baseline in Comparison)
------------------------------------
Self-adaptive EPSO:
  Evolves parameters within population
  w, c1, c2 sampled from distributions
  Better adaptation than fixed/linear

Performance:
  SAEPSO (baseline): ~1557.8 fitness (CEC benchmark)

10.4 APEX-PSO Advantages
------------------------
1. Per-Particle Adaptation: Each particle optimized independently
2. Real-Time Responsiveness: Reacts to swarm state instantly
3. Learned Policy: Discovers non-obvious parameter strategies
4. Multi-Objective: Balances speed, diversity, convergence
5. Generalization: Learned policy works on different problems

Expected Performance:
  APEX-PSO (pretrained): 1374-1400 fitness (15-20% improvement over SAEPSO)

13. TROUBLESHOOTING & TIPS
================================================================================

13.1 Common Issues
------------------

Issue: GPU Out of Memory
  Solution: Reduce batchSize from 512 to 256
  Solution: Reduce bufferSize from 1M to 500K
  Note: Trades learning speed for memory usage

Issue: Loss becomes NaN
  Solution: Reduce learning rate (divide by 2)
  Solution: Add gradient clipping (uncomment in code)
  Solution: Reset network initialization

Issue: Poor fitness improvement
  Solution: Increase training steps per iteration (60 → 100)
  Solution: Verify reward function weights sum to ~1.35
  Solution: Check feature scaling in feature extractor

Issue: Slow convergence
  Solution: Increase learning rate (3e-4 → 5e-4)
  Solution: Reduce warmup period (50 → 30 iterations)
  Solution: Enable environment-specific pretraining

13.2 Optimization Tips
----------------------

For Faster Training:
  • Use GPU acceleration (NVIDIA GeForce preferred)
  • Increase batch size if VRAM available (512 → 1024)
  • Reduce number of episodes (150 → 100)
  • Disable non-essential logging

For Better Performance:
  • Train for more episodes (150 → 200)
  • Use environment-specific reward tuning
  • Implement curriculum learning (start easy, increase difficulty)
  • Ensemble multiple trained agents

For Generalization:
  • Train on diverse CEC functions
  • Vary population sizes (30, 40, 50)
  • Test on functions with different characteristics
  • Monitor out-of-sample performance
